# 투자포인트 중심 검토 작업면 — 설계 v1

작성일: 2026-09-04. 상태: 투자포인트 작성·AI 질문 제안, 정기보고서 수집/변화 대조, 원문·재무·외부 자료 연결, 관심종목 목록과 전체 업데이트 검토함 구현. 중복되던 전역 자료 찾기·포인트 상태판·AI 검토·학습판 메뉴는 제거하고 종목별 기능은 상세 화면에 모았다. 뉴스·리포트는 사용자가 확인한 링크를 직접 연결하는 방식을 유지하며 자동 크롤링과 AI 웹 수집은 범위에서 제외한다. 실제 모델 품질 검증은 보류.

이 문서는 관심종목 검토의 중심을 사용자의 투자 논리로 옮기는 제품 설계다. 수동 기록, AI 질문 제안/채택, 정기보고서 원문 열람·변화 대조, 사용자 연결 근거 기반 AI 검토까지 구현했다. 기능 연결과 실제 모델 품질 검증은 구분한다. 원문 처리의 구체적 범위는 [공시 원문 작업면](DART_SOURCE_READER.md)을 따른다.

## 1. 핵심 결정

- Radar는 발견 경로 중 하나다. Quality / Improvement / Dislocation / Event는 관심종목의 투자 논리나 검토 범위를 제한하지 않는다. 사용자가 직접 등록한 종목은 `discovery: manual`을 유지하고 Radar 통과 근거를 생성하지 않는다.
- 관심종목의 검토 단위는 사용자가 작성한 개별 투자포인트다. 성장, 사업 변화, 경쟁력, 자본 효율, 가치평가 가정 등을 자유롭게 적는다.
- AI는 사용자 논리를 사실로 인정하거나 강화하는 역할이 아니다. 가정을 분해하고, 관련 사실·반대 근거·다른 설명·자료의 공백을 찾는다.
- 기업에 대한 사실, 사용자 가정, AI의 추론을 구분한다. 자료가 논리의 일부를 뒷받침해도 투자 논리 전체가 입증됐다고 표시하지 않는다.
- 투자 매력도 총점, 성공 확률, 적정주가 산출, 매수·매도·보유 지시, 포트폴리오 기능은 만들지 않는다.
- 수치는 원자료와 검증된 계산에서 표시한다. AI 문장이 숫자·단위·비교 기간을 새로 만들어내게 하지 않는다.

## 2. 사용자 흐름과 작성 방식

Radar 후보 발견 → 사용자가 관심종목 등록 → 투자포인트 작성 → 검증 항목 채택 → 자료 대조 → 새 자료의 변화 확인.

### 등록과 첫 작성

- 등록할 때 선택 입력란 `관심을 갖게 된 이유`를 제공한다. 입력하면 첫 투자포인트로 저장한다.
- 당장 작성하지 않아도 등록·자료 수집을 막지 않는다. 대신 `투자포인트 미작성`으로 표시하고 일반 지표 해설로 빈칸을 대신하지 않는다.
- 기존 관심종목에는 빈 작성 영역만 추가한다. Radar 조건으로 투자포인트를 자동 생성하지 않는다.
- 여러 포인트를 각각 작성할 수 있다. 첫 버전은 자유 텍스트와 저장 버튼을 기본으로 하고 복잡한 필수 양식은 두지 않는다.
- 등록과 이유 입력을 함께 보내면 하나의 저장 트랜잭션으로 처리하고, 성공 후 자료 수집을 시작한다. 이미 등록된 종목의 기존 논리를 덮어쓰지 않는다.
- 재등록 시 새로 입력한 이유는 기존 포인트를 유지하고 추가한다. 같은 요청 ID의 재시도는 중복 저장하지 않는다.

### 투자포인트의 사용자 필드

| 필드                 | 입력 정책                                               |
| -------------------- | ------------------------------------------------------- |
| 투자포인트 본문      | 유일한 필수 필드. 사용자가 실제로 적은 문장을 보존      |
| 짧은 제목            | 선택. 미입력 시 본문 첫 줄로 표시                       |
| 예상 확인 시기       | 선택. 불명확하면 미정; AI가 임의의 기한을 확정하지 않음 |
| 기대가 약해지는 조건 | 선택. 반증 조건을 사용자 언어로 기록                    |
| 관련 원문 링크       | 선택. 저장만으로 읽었다고 처리하거나 자동 접속하지 않음 |

구현된 한도는 종목당 활성 포인트 10개, 본문 4,000자, 제목 80자, 포인트당 직접 검증 항목 12개다. `research/thesis-config.json`에 중앙화하고 잘라서 저장하지 않는다. 저장 실패 시 입력을 유지한다. 한도는 종목 선별 기준이 아니라 화면·요청 크기 관리용이다.

명시적 저장과 `저장 전 / 저장됨 / 저장 실패` 표시를 사용한다. 편집 중 종목·탭 이동이나 새로고침에는 미저장 변경 경고를 제공한다. 브라우저 저장소를 원본으로 삼지 않는다.

## 3. 화면 구성

### 종목 상세

- 관심종목은 본문 첫 탭을 `투자포인트`로 연다. 기존 `핵심 현황 / 재무 추이 / 가격·거래량 / 공시`는 유지한다. 직접 링크로 지정한 탭은 우선한다.
- 미등록 Radar 후보는 기존 기본 자료 화면을 유지하고 등록 진입점만 제공한다.
- 좌측: 관심종목 목록과 탐색. 표시 정보는 포인트 미작성, 새 자료 있음, 검토 결과 갱신 필요 같은 작업 상태만 사용한다.
- 중앙: 포인트의 짧은 목록, 선택한 포인트 편집기, 채택한 검증 항목. 긴 분석 보고서를 쌓지 않는다.
- 우측: 선택한 포인트의 `검토 결과 / 연결 자료 / 발견 경로` 탭. 발견 경로에 과거 Radar 기록을 둔다.
- 현재 우측 `내 검토`는 저장한 포인트와 질문 수를, `AI 질문`은 별도 동의 후 생성한 질문을 보여준다. 편집기 상단의 `연결 자료 N개` 버튼으로 이 패널을 바로 열 수 있다. `연결 자료`는 사용자가 직접 고른 원문 문단·표와 재무 기간·지표를 `뒷받침 / 약화 / 미확인`으로 묶어 관계별 개수·메모·출처 버전과 함께 보여준다. 빈 관계 그룹도 0건으로 남긴다. `발견 경로 / 지표·출처`는 유지한다. AI가 자료와 논리를 자동 대조한 검토 결과는 아직 구현하지 않았다.
- 우측 검토 결과는 `뒷받침 자료 / 반대 자료·다른 설명 / 미확인 / 새로 달라진 내용`으로 나눈다. 한쪽 근거가 없으면 해당 확인 범위와 함께 표시한다.
- 근거를 선택하면 문서 절·표·짧은 원문 발췌 또는 재무 차트의 해당 기간으로 연결한다. 출처 확인 화면에서 포인트로 돌아갈 수 있어야 한다.
- 좌측·중앙·우측은 각각 내부 스크롤한다. 1280×720 기준 문서 전체의 수평·세로 스크롤 없이 주요 작업에 접근해야 한다. 좁은 화면에서는 양옆 패널을 서랍으로 연다.
- 색상은 근거 관계·자료 상태를 구분할 뿐 투자 신호를 뜻하지 않는다. `확인됨` 하나로 사실 확인과 논리 입증을 혼합하지 않는다.

### 관심종목 목록과 기존 명칭

- 목록에는 대표 투자포인트 한 줄과 `자료 변경 / AI 검토 없음 / 이전 자료 기준` 상태를 표시한다. AI 추천순 정렬은 하지 않는다.
- 기존 Radar 우측 `Evidence Copilot`은 `선정 근거 요약`으로 이름을 바꿨다.
- 기존 지표 정의는 `지표 도움말`로 유지한다. 유료 Radar 해설은 새 중심 작업의 필수 과정이 아니며 신규 기본 진입점에서 제외한다.

## 4. AI 작업을 세 가지로 분리

### A. 검증 항목 제안

입력: 저장된 한 개의 투자포인트, 사용자가 입력한 선택 항목. 기본적으로 다른 포인트와 개인 기록은 제외한다.

출력: 주장의 구성, 명시·암묵적 가정, 확인 질문, 반증 질문, 필요한 자료 종류. 입력에 적힌 기업 사실도 `사용자 주장 · 원문 확인 전`으로 취급한다. 논리가 모호하면 확인 질문을 제안하고 빈칸을 임의로 채우지 않는다.

예시(가상): `증설 → 출하 증가 → 이익률 개선`이라는 논리라면 가동 시점, 주문·출하, 가동률, 고정비·감가상각, 자금 부담을 각각 확인할 항목으로 제안한다. 증설됐다는 사실이나 인과관계가 이미 확인됐다고 쓰지 않는다.

2A 구현: 사용자가 질문을 선택·수정해 한 번에 채택한다. 미선택 질문은 추가하지 않는다. 이후 수정은 내 검증 항목에서 한다. 같은 결과에서 두 번째 묶음 채택은 지원하지 않으며 동일 요청 재시도는 중복 추가하지 않는다. 제안은 사용자의 본문을 덮어쓰지 않는다. AI 없이도 질문을 직접 작성할 수 있다.

입력은 종목명·코드와 한 포인트의 제목/본문/시기/반증 조건/기존 질문이다. 관련 링크 필드·다른 포인트·개인 기록·수집 자료는 제외한다. 본문에 직접 쓴 내용은 미리보기 그대로 포함한다. 결과는 최대 6개이며 각 질문에 정확한 사용자 문구 인용, 질문 이유, 필요한 자료 종류·확인할 부분·조건부 반증 관측을 붙인다. 일반 가설에는 반증 질문이 최소 하나 필요하며, 모호하면 `가설 구체화` 질문을 낸다.

### B. 수집 자료와 논리 대조

입력: 포인트의 저장 버전, 사용자가 채택한 검증 항목, 해당 종목의 관련 원문·재무 관측값과 출처 상태. 자료는 최신 보강 자료를 사용하고 과거 Radar 자료는 별도 참고로만 구분한다.

각 검증 항목에 대해 다음을 반환한다.

- `관측 사실`: 실제 문서·표·계산에 명시된 내용과 근거 ID.
- `논리와의 관계`: 뒷받침 / 약화 / 직접 관련 불명 중 하나와 AI의 해석. 확실한 인과로 확대하지 않는다.
- `다른 설명·반대 근거`: 가능한 가설이면 그렇게 표시하고 확인 자료를 요구한다. 근거를 못 찾았다고 위험이 없다고 하지 않는다.
- `미확인 자료·다음 확인`: 구체적인 자료나 질문. 단순히 "추가 확인 필요"만 반복하지 않는다.

질문·가설에는 사실 근거가 없을 수 있다. 기업 사실로 출력하려면 원문·관측값 연결이 필수다. 질문을 사실인 것처럼 전제해서 쓰는 것도 품질 평가에서 차단한다.

### C. 새 자료와 이전 검토 비교

자료 수집 시 프로그램이 접수번호·문서 해시·동일 기준 재무 값 변화를 먼저 감지한다. 이 단계에는 AI 호출이 없다.

사용자가 `변경 자료 대조`를 누르면 같은 포인트·검증 항목 버전의 이전 검토 자료와 새 자료를 비교한다. 무엇이 추가·수정됐으며 어떤 항목과 관련되는지 원문 전후 비교로 표시한다. 자료가 일부 누락되거나 연결/별도·분기 기준이 달라 비교할 수 없으면 비교 불가로 남긴다.

- 포인트 자체를 수정했다면 자료 변화와 논리 변화를 분리한다. 다른 논리의 검토 결과를 그대로 비교하지 않는다.
- AI 결과를 열었다고 확인 처리하지 않는다. `이 검토 결과 확인`을 명시적으로 누른다.
- 이 확인은 기존 `watchlist_reviews`의 자료 확인과 독립적이다. 확인했다고 논리에 동의하거나 가정이 입증된 것은 아니다.
- 캘린더 자동 등록·정기 AI 실행은 초기 범위 밖이다. 입력한 확인 시기는 사용자 메모이며 모든 사업 변수를 빠짐없이 추적한다는 보장은 없다.

## 5. 자료의 실제 범위와 필요한 선행 작업

현재 코드에서 확인한 자료는 일별 가격, 최근 8개 분기 재무 및 재무 원자료 JSON, 최근 1년 공시 제목·분류·접수 링크다. `StockEvent`에는 공시 본문이 없다. 공장 가동, 고객사, 수주 조건, 경쟁력, 주석상 일회성 요인은 현재 자료만으로 확인할 수 있다고 가정하지 않는다.

따라서 원문 수집·추출을 B의 선행 작업으로 둔다.

1. 사용자가 등록한 종목 범위에서 DART 원문과 해당 보고서의 사업·주석·정정 내용을 수집한다. 구현 전에 실제 원문 제공 방식·이용 조건을 확인한다.
2. 접수번호, 문서 제목, 공시일, 수집일, 문서 해시, 절/표 식별자, 원문 링크, 추출 상태를 저장한다. 최신이라는 이유로 과거 원문을 덮어쓰지 않는다.
3. 문서 절과 표를 나누되 단위·연결/별도·보고 기간을 보존한다. 최초에는 실제 검증 가능한 형식만 지원하고 OCR·첨부파일 미지원은 명시한다.
4. 논리와 가까운 자료만 골라 AI에 전달하되 긍정 키워드만 검색하지 않는다. 부채·비용·계약 조건·정정 등 반대 자료도 검색한다.
5. 자료 범위에는 수집 기간, 읽은 문서/절, 미처리 문서, 실패한 출처, 오래된 자료를 표시한다. 일부 검색 결과로 "모든 공시를 확인"했다고 쓰지 않는다.
6. 수요·시장점유율·경쟁사·밸류에이션 비교 자료가 필요하지만 수집되지 않았다면 자료 공백으로 남긴다. 외부 뉴스·웹 검색·IR 자료 연동은 후속 범위이며 자동 활성화하지 않는다.

원문 링크가 있다는 사실만으로 본문을 읽었다고 표시하지 않는다. 본문 수집 전에는 A와 수동 기록을 사용할 수 있지만, B는 확보된 재무 관측과 제한된 자료에 대해서만 명시적으로 제공한다.

## 6. 저장·버전·충돌 처리

수집기는 `watchlist.detail_json`을 갱신하므로 투자포인트·사용자 상태·AI 결과를 그 JSON에 넣지 않는다. 같은 SQLite의 별도 테이블에 저장한다. 검증 질문은 `content_json.checks`에 넣고 본문과 같은 버전으로 원자적으로 저장한다.

| 데이터              | 설계 테이블                                                                                                                    | 보존 원칙                                                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 사용자 포인트       | `investment_theses`, `investment_thesis_revisions`                                                                             | 본문·선택 필드·수정 시각·버전. 변경 전 문장 보존                                                                                                           |
| 검증 항목           | `investment_theses.content_json.checks` 및 같은 수정 버전                                                                      | 직접 작성 또는 AI 제안에서 선택·수정 채택; 본문과 같은 버전                                                                                                |
| 원문·관측 근거      | `filing_documents`, `filing_document_versions`, `research_evidence`, `research_financial_evidence`, `research_manual_evidence` | 수동 연결 구현. 포인트 revision·불변 문서 위치/발췌, 재무 기간/지표/값/기준/출처 상태, 또는 사용자 입력 링크·제목·출처·날짜·본문 snapshot과 관계·메모 보존 |
| AI 요청과 결과      | `thesis_ai_runs`, `thesis_evidence_ai_runs`                                                                                    | 글 기반 질문과 연결 근거 기반 검토를 분리. 입력·근거 signature·모델·프롬프트·오류·사용량 보존                                                              |
| 공유 유료 요청 한도 | `ai_request_attempts`                                                                                                          | 2A 구현: 두 AI API의 요청·진행 lease·완료 시각. 재시작/여러 프로세스 공유                                                                                  |
| 사용자 확인         | `research_update_states`, `investment_thesis_status`                                                                           | 업데이트별 확인 메모와 사용자가 직접 정한 가설 상태. 출처 수집·AI 결과와 분리                                                                              |

검토 입력 버전은 포인트·채택 항목·문서/관측값 집합·출처 상태를 포함한다. 실행 중 입력이 바뀌면 결과를 현재 검토에 적용하지 않고 `이전 자료 기준`으로 보존한다. 같은 문서가 유지돼도 시간이 지나면 자료 신선도는 다시 계산한다.

저장은 클라이언트 revision과 서버 revision을 트랜잭션에서 비교한다. 충돌은 409와 기존 입력 유지로 처리하고 마지막 저장자가 이전 내용을 몰래 덮어쓰지 않는다. 새 포인트 생성·AI 요청은 요청 ID로 중복 실행을 방지한다.

포인트 제거는 보관 처리하며 되돌릴 수 있게 한다. 관심종목 해제·Radar 탈락·재등록·자료 재수집으로 포인트나 원문·채택 검증 항목을 삭제하지 않는다. 활성 사용자 논리만 최신 화면에 표시한다.

스키마 변경 전에 기존 SQLite 백업을 검증한다. 백업 manifest·무결성 검사·복구 테스트에 신규 테이블과 근거 원문 파일을 포함한다. 기존 백업은 "투자포인트 기능 도입 전"으로 정상 복구할 수 있게 한다. 영구 AI 검토 기록은 재생성 가능한 캐시와 구분한다. 백업 용량 초과 시 자료를 조용히 생략하지 않는다. 로컬 DB·백업의 개인 논리는 기본적으로 암호화되지 않았음을 안내한다.

## 7. 예정 API 계약과 전송 경계

모든 쓰기는 로컬·동일 출처 검증을 유지한다. 직접 질문은 POST/PATCH의 `content.checks`로 함께 저장하며, 업데이트와 투자포인트 상태는 별도 API에서 관리한다.

| 요청                                                            | 목적                                                                                                                                |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/watchlist/{code}/theses`                              | 포인트·버전·작업 상태 읽기; 외부 호출 없음                                                                                          |
| `POST /api/watchlist/{code}/theses`                             | 사용자 포인트 생성; 요청 ID 포함                                                                                                    |
| `PATCH /api/watchlist/{code}/theses/{id}`                       | 내용 수정·보관·복구; revision 필수                                                                                                  |
| `POST /api/watchlist/{code}/theses/{id}/analysis`               | 2A 질문 제안만 실행. 요청 ID·revision·서버 생성 signature·consent 필수                                                              |
| `GET /api/watchlist/{code}/theses/{id}/analysis`                | 설정·전송 범위·가장 최근 요청/결과 조회; 외부 호출 없음                                                                             |
| `POST /api/watchlist/{code}/theses/{id}/analysis/{runId}/adopt` | revision과 선택한 질문 인덱스/편집 문구. 버전·질문·채택 출처를 한 트랜잭션에 저장                                                   |
| `GET/POST /api/watchlist/{code}/evidence-links`                 | 포인트별 원문 연결 조회 / 정확한 포인트·문서·절·블록 버전 연결. 외부 호출 없음                                                      |
| `PATCH /api/watchlist/{code}/evidence-links/{id}`               | 원문 연결 보관·복구. 실제 행 삭제 없음                                                                                              |
| `GET /api/watchlist/{code}/documents/search`                    | 로컬 DART 추출본 본문 검색. 보고서·목차 분류·현재/전체 저장 버전 필터, 검색 범위와 실패 경고 포함. 외부 호출 없음                   |

| `PATCH /api/watchlist/{code}/financial-evidence/{id}`           | 재무 관측 연결 보관·복구. 실제 행 삭제 없음                                                                                         |
| `GET/POST /api/watchlist/{code}/manual-evidence`                | 뉴스·리포트·IR·산업 자료 링크 또는 직접 메모 조회/저장. URL 본문 자동 수집·검증 없음                                                |

| `GET/POST /api/watchlist/{code}/theses/{id}/evidence-review`    | 연결 자료 전송 범위 조회 / 명시적 동의 후 충돌·공백·검증 질문 제안                                                                  |

사용자가 포인트 작성에 동의했다는 이유로 개인 글을 즉시 전송하지 않는다. 이 설계 동의도 현재 앱의 전송 허용 범위를 자동으로 바꾸지 않는다.

- 저장·열람·자료 갱신은 AI를 실행하지 않는다.
- AI 실행 전 해당 포인트의 저장 문장, 채택 항목, 전송할 자료 범위와 유료 호출 안내를 보여준다.
- 첫 실행은 `선택한 투자포인트를 외부 AI에 보내 검토`를 명시적으로 확인한다. 다른 포인트나 기존 개인 검토 기록은 기본 제외한다.
- 입력 크기·한도 초과는 사전 안내한다. 사용자 논리를 조용히 잘라서 전송하지 않는다.
- 원문·사용자 입력은 지시가 아니라 데이터로 취급한다. AI에 임의 URL 접속, 로컬 파일 읽기, SQL 실행, 포인트 자동 수정 도구를 제공하지 않는다.
- 인증 키·원시 예외·개인 본문을 일반 로그에 남기지 않는다. 캐시도 개인 자료이므로 공개 JSON/Git에 넣지 않는다.
- 요청 ID·전송 범위·모델·입력 버전·시각·사용량을 로컬에 기록한다. 첫 버전은 기존 모델 연결을 재사용하되 품질 검증 없이 최종 모델로 확정하지 않는다.
- 최대 동시 유료 작업 1개, 시간당 요청 한도·시간 제한·토큰 한도를 중앙 설정한다. 앱의 여러 AI 경로가 한도를 공유하도록 구현한다. 재시작·중복 클릭·여러 서버 프로세스에도 중복 청구 방지가 유지되게 검증한다. 이는 공급자 계정 전체의 금액 상한은 아니다.
- 자동 유료 재시도는 하지 않는다. 실패해도 기존 투자포인트·자료·이전 검토 결과를 유지한다.

## 8. 구현 순서와 완료 기준

### 1단계 — 투자포인트 작업면

구현 완료: 포인트 작성·수정·보관·복구, 직접 검증 항목 작성, 관심종목 목록 연결, 충돌 방지, 백업 호환성. 기존 Radar Copilot 명칭도 정리했다. AI 키 없이 사용하며 외부 전송하지 않는다. 과거 수정 버전은 저장하되 버전 탐색·특정 버전 복원 화면은 아직 없다. 저장 전 경고는 제공하지만 미저장 초안을 브라우저 강제 종료 후 복구하지는 않는다.

완료 기준: 새로고침·재시작·재수집·해제 후 재등록에도 입력 보존; 두 탭 동시 수정 충돌 처리; 미저장 경고; 키 미설정 상태; 빈 포인트·긴 문장; 좁은 화면과 내부 스크롤; 원문과 AI 제안의 구분.

### 2단계 — 검증 항목 제안과 원문 기반 대조

2A 구현 완료(실제 모델 품질 제외): 별도 동의·전송 미리보기·질문 카드·선택/수정 채택·불변 입력 기록·버전 충돌·유료 요청 중복 방지·공유 한도·백업/복원. 재시작 시 pending은 자동 재전송하지 않고 제한 시간이 지난 결과 미확인은 별도 표시한다. 복구 사본의 pending은 오류 상태로 바꿔 자동 재개를 막는다. 수동 평가 세트는 [THESIS_AI_EVALUATION.md](THESIS_AI_EVALUATION.md)이며 아직 실행하지 않았다.

A의 제안/채택을 먼저 연결한다. 동시에 DART 본문·주석 저장과 출처 탐색기를 준비하고, 추출 검증 후 B를 연결한다. 금융 수치 계산은 기존 검증된 코드가 맡고 AI는 근거의 관계를 설명한다. 제목-only 자료를 본문 분석처럼 쓰는 출시는 하지 않는다.

완료 기준: 선택 포인트만 전송; 동의 전 외부 호출 0; 입력 변경·캐시 충돌 방지; 거절·시간 초과·부분 실패 처리; 원문 인용 위치 검증; 서로 다른 기간/회계 기준 혼합 방지; 실제 모델 답변 수동 평가.

### 3단계 — 변화 대조와 관심종목 팔로업

저장된 두 정기보고서의 수동 변화 대조와 관심종목 업데이트 검토함을 구현했다. 같은 목차의 문단·표를 정렬하고, 새 공시·재무·원문 저장·수집 오류를 개별 확인 상태로 관리한다. `/watchlist`는 관심종목 목록과 전체 업데이트만 제공하고, 투자포인트·연결 자료·AI 질문은 종목 상세에서 사용한다. 자동 뉴스 수집·자동 중요도 판정·정기 AI 실행은 포함하지 않는다.

완료 기준: 첫 검토는 과거 자료를 전부 "신규"로 세지 않음; 이전 문서와 원문 전후 비교; 누락을 호재/악재로 추정하지 않음; 결과 열람으로 자동 확인하지 않음; 기존 팔로업 확인 상태와 독립.

## 9. AI 품질 기준

실제 모델 평가 전에는 `기능 연결됨`과 `해설 품질 검증됨`을 구분한다. 자연스러운 한국어와 JSON 형식 통과만으로 완료라고 하지 않는다.

초기 평가 세트는 실제 출처와 사람이 확인한 항목을 기준으로 최소 12개를 구성한다: 근거가 있는 성장 가설 2개, 반대 사실이 있는 가설 2개, 모호한 가설 2개, 자료 부족 2개, 정정/기간·연결 기준 차이 2개, 입력·문서 내 지시문 공격 2개. 실제 기업을 사용하더라도 기대 정답은 투자 성과가 아니라 원문과 관계의 정확성이다.

- 없는 기업 사실·출처·인용문·수치, 금지된 투자 지시, 다른 종목 개인 정보 전송이 나오면 출시 차단.
- 긍정 근거뿐 아니라 평가자가 지정한 주요 반대 근거와 자료 공백을 드러내야 한다.
- 주장에 없는 인과를 확정하거나 질문 형식으로 허위 사실을 전제하지 않아야 한다.
- 원문 출처 연결을 검증해도 해석의 진실성이 자동 보장된다고 안내하지 않는다.
- 고정 지표 도움말과 나란히 검토하여 구체적인 원문 연결·새로운 확인 질문·검토 시간 절감이 있는지 평가한다. 차별적 도움이 없으면 AI 범위를 늘리거나 모델만 교체하지 말고 입력 자료와 작업 설계부터 수정한다.

현재 미확정 항목: 실제 DART 문서 형식별 추출 범위, 원문 분량에 따른 요청 비용, 최종 모델. 자료 수집 실험과 평가 결과로 결정하며, 투자포인트 저장 UI의 구현을 막지는 않는다.
