# Value Investment Dashboard

시각적 탐색과 근거 확인을 중심으로 다시 설계하는 개인용 투자 학습 대시보드입니다.

전체 수집·Radar·DART 원문·AI 작업은 **로컬 PC**에서 실행합니다. 모바일 배포는 로컬 기능을 서버에서 재실행하지 않고, PC가 게시한 읽기용 스냅샷을 열람하고 종목 메모를 남기는 별도 모드입니다.

## Product direction

- Radar는 종목 추천기가 아니라 아이디어 발견 도구입니다.
- 단일 종합점수보다 포착 근거, 반대 근거, 데이터 커버리지를 함께 보여줍니다.
- 관심종목의 중심은 사용자가 적은 투자포인트입니다. AI는 향후 이를 검증할 질문과 원문 대조를 보조하며 리포트·투자의견으로 대신하지 않습니다.
- 모든 데이터는 기준일, 수집 시각, 출처, 최신성 상태를 가집니다.
- 포트폴리오 운용과 주문 기능은 범위에 포함하지 않습니다.

## Current slice

현재 화면은 KOSPI·KOSDAQ 전체시장을 새로 수집한 Radar 실행 결과를 표시합니다. 2026-09-04 실행은 상장 보통주 2,528개 중 시가총액 300억원 이상 2,159개의 가격을 확인하고, 20일 중앙 거래대금 2억원·가격 이력 조건을 통과한 1,311개를 평가했습니다. DART 주요재무는 1,308/1,311개를 확보했습니다. 강화 규칙 v7은 넓어진 평가 Universe에서 Quality 5개, Improvement 9개, Dislocation 3개, Event 16개를 찾았고 중복 제거 후보는 33개입니다. 렌즈별 개수 상한은 없습니다.

v7은 사전 규모·유동성 하한은 완화하되 렌즈 내부의 수익성·성장·가격 괴리·이벤트 반응 조건은 강화합니다. 정확한 수치는 `radar/rules.v1.json`과 화면의 `조건 보기`를 기준으로 합니다.

`/markets`는 FinanceDataReader 기반 글로벌·한국 벤치마크 11개와 로컬 전체시장 가격 이력으로 계산한 breadth를 표시합니다. 각 자산은 독립 수집되며 누락·지연 상태와 원천 관측일을 화면에 남깁니다.

리서치 확장 화면은 기존 투자포인트를 복제하지 않고 같은 로컬 저장소를 재사용합니다.

- 종목 상세 `Research View`: 투자포인트·연결 근거·실제 재무·사업 KPI·최근 판단 기록·자료 상태를 읽기 전용으로 요약합니다. 발표 자료 생성 화면이 아닙니다.
- 종목 상세 `사업 KPI`: 종목별 가격(P)·수량(Q)·비용(C) 또는 고유 사업 지표를 정의하고, 기간별 실제값·당시 예상값·출처를 원수치로 추적합니다.
- 종목 상세 `리서치 로그`: 새 인사이트, 확인 질문, 논리 변경, 세션 피드백, 보류·검토 중단·재검토 이유를 시간순으로 기록합니다.
- `/compare`: 관심종목 2~5개의 실제 재무값과 같은 이름의 사용자 KPI를 백분위·종합점수 없이 나란히 비교합니다.
- `/learning`: 책·특강·아티클의 요약보다 배운 점, 관점 변화, 적용 아이디어와 반론을 기록하고 관심종목에 연결합니다.

KPI·로그·학습 기록의 제거는 복구 가능한 보관 처리이며, AI 호출이나 외부 자료 자동 수집은 발생하지 않습니다. AI 챌린지와 전역 검색은 실제 기록이 충분히 쌓인 뒤 품질 검증과 함께 추가합니다.

```bash
npm install
npm run dev
```

로컬 모바일 미리보기는 `/mobile`에서 확인할 수 있습니다. Supabase 환경변수가
없으면 현재 로컬 자료를 읽기 전용으로 구성하며 모바일 메모 저장은 비활성화됩니다.

## Full-market Radar run

Radar 규칙은 `radar/rules.v1.json`에 버전 관리합니다. 전체 실행은 KRX 상장 목록과 완료 거래일 가격을 새로 확인하고, DART 기업코드·최근 8개 분기 재무·최근 120일 중요 공시를 수집한 뒤 동일 기준일의 SQLite 스냅샷에서 네 렌즈를 평가합니다. 모든 단계가 검증된 경우에만 `public/data/radar/latest.json`을 원자적으로 교체하며 실패하면 기존 게시 결과를 유지합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements-radar.txt
Copy-Item .env.example .env.local
# .env.local의 DART_API_KEY를 입력한 뒤 실행
.\.venv\Scripts\python.exe -m scripts.run_full_market_radar
```

동일한 검증 스냅샷에서 규칙만 조정해 다시 평가:

```powershell
.\.venv\Scripts\python.exe -m scripts.reevaluate_radar
```

시장 상황판 최신 수집:

```powershell
.\.venv\Scripts\python.exe -m scripts.collect_markets
```

최신성 정책:

- 매 실행마다 KRX Universe와 DART 기업코드를 갱신합니다.
- 가격은 장중이면 직전 완료 거래일, 장 마감 뒤면 당일 완료 거래일까지 검증합니다.
- 동일 완료 시장일의 가격 체크포인트만 재사용하며 날짜나 대상 종목 해시가 달라지면 전량 재수집합니다.
- DART 최신 2개 주요재무 기간, 최신 전체재무 기간, 최근 이벤트 구간은 강제 갱신합니다.
- 과거 확정 구간만 캐시하고 실패·누락·stale 상태를 정상값으로 게시하지 않습니다.

검증:

```bash
npm run test:radar
npm run lint
npm run build
node --experimental-strip-types --test tests/research-system.test.mjs
```

전체시장 수집기는 로컬 Python에서 실행하고 검증된 스냅샷을 로컬 화면에 반영합니다. 수집 시간 제한을 배포 플랫폼에 맞춰 줄이지 않습니다.

## 로컬 백업·복구

`npm run dev`는 서버 시작 전에 검증된 자료 백업을 만듭니다. 실행 중 매일/주기적으로 저장하는 기능은 아니므로 중요한 등록·검토·수집 후에는 `npm run backup`도 실행하세요. 자동 삭제는 하지 않습니다. 첫 실행으로 DB가 없을 때만 건너뛰며, 기존 DB의 백업이 실패하면 서버 시작을 멈추고 오류를 표시합니다.

기본 백업 위치는 프로젝트 폴더 밖의 `../value-invest-dashboard-backups`입니다. `.env.local`의 `DASHBOARD_BACKUP_DIR`에 다른 드라이브 경로를 지정할 수도 있습니다. 동일 디스크의 백업만으로 디스크 고장까지 대비할 수는 없습니다.

```powershell
npm run backup
npm run backup:list
npm run backup:verify -- "C:\Users\khdkf\value-invest-dashboard-backups\backup-실제파일명.zip"
npm run backup:restore -- "C:\Users\khdkf\value-invest-dashboard-backups\backup-실제파일명.zip" --to "C:\Users\khdkf\value-invest-dashboard-recovered"
```

- 보관: 관심종목(해제한 종목 포함), 투자포인트·직접 작성한 검증 항목·수정 버전·보관 상태, 상세 자료, 검토 확인 기준, 작업 기록, 재무 원자료. DB는 SQLite 온라인 백업으로 WAL에 남아 있는 변경도 포함합니다. 개인 글과 백업은 기본적으로 암호화되지 않습니다.
- 참고 사본: Radar 규칙, 연구 설정·스키마, 게시된 Radar·시장·종목 JSON. `context/`에 별도로 보관하며 서로 같은 시점의 전체시장 DB라는 의미는 아닙니다.
- 제외: `.env`·API 키 설정, 소스 코드, 전체시장 수집 DB/캐시, 로그, Python/Node 설치 파일. 전체 개발 환경의 백업은 아닙니다.
- 수집 중인 종목은 일관된 DB 스냅샷의 중간 결과만 포함하고 해당 종목의 재무 원자료 캐시는 제외합니다. 백업에 경고를 남기며, 복구 시 진행 중 작업은 자동 재개하지 않고 재시도 필요 상태로 바꿉니다.
- 모든 파일의 SHA-256/크기와 DB 무결성·항목 수를 검증한 뒤 ZIP을 게시합니다. 손상되거나 알 수 없는 경로·버전의 백업은 복구하지 않습니다. 해시는 우발적 손상 검사이지 신뢰할 수 없는 사람이 만든 백업의 진위 보증은 아닙니다.
- 복구는 **존재하지 않는 새 폴더만** 허용합니다. 현재 자료를 덮어쓰거나 서버가 사용하는 저장소를 자동 전환하지 않습니다.

복구 자료 확인 후 서버와 수집기를 종료하고 `.env.local`의 `RESEARCH_STORAGE_DIR`을 복구 폴더 안의 `research` 절대 경로로 설정한 뒤 서버를 다시 시작하세요. 예: `RESEARCH_STORAGE_DIR=C:/Users/khdkf/value-invest-dashboard-recovered/research`. 기존 저장소는 그대로 남습니다. `context/`의 Radar·시장 스냅샷·설정은 자동 적용하지 않으므로 필요할 때 별도로 확인하세요.

백업 정책·한도는 `research/backup-config.json`, 수동 도구는 `scripts/local_backup.py`에 있습니다. 수집/원본 수정은 하지 않으며 네트워크 호출도 없습니다.

## 관심종목 팔로업

- `/watchlist`는 `관심종목 목록 → 종목 상세`를 기본 흐름으로 사용합니다. 전역 메뉴는 `관심종목/업데이트`만 남기고, 자료 연결·투자포인트·AI 검토는 선택한 종목의 상세 화면에서만 엽니다.
- Radar 후보 외에도 `종목 직접 추가`에서 최신 로컬 KRX 상장 목록을 종목명·종목코드로 검색해 등록할 수 있습니다. 직접 추가 종목은 Radar 포착 근거를 만들지 않고 `직접 추가` 출처를 유지하며, 이후 가격·재무·공시 수집과 투자포인트 관리는 기존 관심종목과 동일하게 진행합니다.
- 업데이트 검토함은 새 공시·재무 변화·새로 저장한 원문·수집 오류를 항목별로 표시합니다. 열람만으로 확인 처리하지 않으며, 검토 메모와 `확인됨/다시 확인` 상태는 `research_update_states`에 별도로 저장합니다.
- 종목 상세의 투자포인트 화면에서 공시·재무·외부 자료를 연결하고 AI 질문을 요청합니다. 외부 검색 결과는 자동 수집·검증하거나 중요도로 정렬하지 않으며, 연결 자료나 AI 결과가 사용자 판단을 자동 변경하지 않습니다.
- 첫 방문은 과거 자료를 새 항목으로 세지 않습니다. `현재 자료 확인` 버튼을 누른 이후의 공시 접수번호·재무 값/접수번호 차이를 표시합니다. 열람, 목록 조회, 자료 갱신만으로 확인 처리하지 않습니다.
- 확인 기준은 `watchlist_reviews` 별도 테이블에 저장합니다. 시간보다 접수번호/값을 비교하므로 과거 공시 추가 수집도 감지합니다. 조회 기간에서 빠진 공시의 확인 기록도 유지합니다. 재무 수집 시각만 바뀌면 수정으로 세지 않습니다.
- 확인 요청에는 표시된 자료의 버전을 포함합니다. 동시에 자료가 바뀌거나 다른 화면에서 확인 처리하면 409로 막아, 보지 않은 자료가 확인 처리되지 않도록 합니다. 수집 중에는 확인할 수 없고, 실패한 출처의 이전 확인 기준은 유지합니다.
- 실적 증감률은 동일 연결/별도 기준, 전년 동기 값이 양수인 경우에만 표시합니다. 결측·0·음수 기준값의 증감률은 `—`입니다. 가격은 실제 원 단위이며 확인 시점의 종가와 비교합니다.
- `research/config.json`: 최신 수집 후 72시간이 지났거나 수집 시각이 미확인이면 자료 점검으로 표시합니다. 이 값은 수집 신선도 기준이지 시세 실시간성 보장이 아닙니다.
- API: `GET/PATCH /api/watchlist/workbench`, `GET /api/watchlist/followup`, `POST /api/watchlist/{code}/review` (`revision`). 상세 연결은 `?tab=thesis|price|financials|events|documents`, 공시 전체 보기는 `&scope=all`입니다.
- 목록 상태 확인은 저장소를 다시 읽습니다. 우측 `자료 갱신`은 해당 종목의 실제 수집 작업을 실행합니다. Radar 조건·판정은 변경하지 않습니다.

### 투자포인트 작업면 — 1단계 구현

- Radar 후보에서 관심종목 등록 시 선택적으로 이유를 입력합니다. 등록과 글 저장은 함께 성공하거나 함께 실패하며, 성공 후 자료 수집을 시작합니다. 재등록 시 기존 글은 유지하고 새로 입력한 이유만 추가합니다.
- 등록 종목의 기본 화면은 `투자포인트`입니다. 직접 지정한 재무·가격·공시 탭 링크는 유지합니다. 기존 종목에 Radar 조건을 투자 논리로 자동 입력하지 않습니다.
- 여러 포인트를 작성하고 제목·본문·확인 시기·기대가 약해지는 조건·관련 원문 링크·직접 확인할 질문을 명시적으로 저장합니다. 종목당 활성 10개, 본문 4,000자, 질문 12개 한도는 `research/thesis-config.json`에 있습니다. 초과 입력을 잘라서 저장하지 않습니다.
- 보관함 이동과 복구가 가능하며, 해제·재등록·재수집으로 글을 삭제하지 않습니다. 수정 버전은 저장소에 보존합니다. 과거 버전 탐색 UI는 아직 없습니다.
- 여러 화면에서 같은 포인트를 수정하면 409로 충돌을 알리고 현재 입력과 최신 저장본을 비교합니다. 저장 전 탭·종목 이동과 새로고침에는 경고합니다. 저장하지 않은 글은 브라우저를 강제 종료하면 복구되지 않습니다.
- 중앙 편집기와 좌우 패널은 독립 스크롤합니다. 우측 `내 검토`는 선택한 **저장본**과 작성한 질문 수를 표시합니다. AI 결과인 것처럼 표시하지 않습니다.
- `공시 원문`의 문단·표에서 연결 버튼을 눌러 선택한 투자포인트에 근거를 붙일 수 있습니다. 관계는 `뒷받침 검토 / 반대·약화 검토 / 참고·미확인` 중 하나이며, 사용자의 분류일 뿐 사실 확인이나 논리 입증을 뜻하지 않습니다.
- 연결에는 포인트 수정 버전, 공시 접수번호·불변 저장 버전, 절·블록·XPath, 당시 원문 발췌와 선택 메모가 함께 저장됩니다. 원문 재수집과 포인트 수정으로 과거 연결을 덮어쓰지 않으며 연결 해제는 복구 가능한 보관 처리입니다.
- `재무 추이`에서는 선택한 지표와 분기를 투자포인트에 연결할 수 있습니다. 서버가 저장된 DART 재무 값·연결/별도 기준·접수번호·출처 상태를 다시 확인해 불변 관측값으로 저장하며, 결측을 0으로 바꾸거나 수치와 가설의 인과를 자동 판정하지 않습니다.
- 투자포인트 편집기 상단의 `연결 자료 N개` 버튼은 해당 포인트의 검토 근거를 바로 엽니다. 데스크톱에서는 우측 패널, 좁은 화면에서는 근거 서랍을 사용합니다.
- 투자포인트의 `연결 자료`에는 원문 발췌와 재무 관측이 함께 표시됩니다. `뒷받침 / 약화 / 미확인` 요약과 그룹별 자료를 비교하며, 빈 그룹도 숨기지 않습니다. 관계 분류와 메모는 사용자 판단이며 포인트가 수정되면 이전 버전에서 연결한 자료임을 알립니다.
- 저장·열람·자료 갱신으로 개인 글을 AI에 전송하지 않습니다. 글 기반 질문 제안과 연결 자료 기반 검토는 서로 다른 명시적 전송 작업이며, 공시 변화 대조는 AI 없이 실행합니다.
- 저장: `investment_theses`, `investment_thesis_revisions`, `research_evidence`, `research_financial_evidence`, `research_manual_evidence`, `investment_thesis_status`, `research_update_states`, `thesis_evidence_ai_runs`. 사용자 상태와 AI 결과는 수집 자료와 분리합니다.
- API: 기존 투자포인트·공시·재무 근거 API에 `GET/POST /api/watchlist/{code}/manual-evidence`, `GET /api/watchlist/{code}/documents/compare`, `GET/POST /api/watchlist/{code}/theses/{id}/evidence-review`가 추가됐습니다. 쓰기는 같은 출처의 로컬 요청만 허용하며 revision·입력 signature·생성 요청 ID를 검사합니다.

검증: `npm run test:thesis`, `npm run test:stock`, `npm run test:evidence`, `npm run test:documents`, `npm run test:workbench`, `.venv\\Scripts\\python.exe -m unittest discover -s tests -p test_*.py`. 테스트는 별도 저장소를 사용합니다. 상세 경계는 [투자포인트 작업면 설계](docs/INVESTMENT_THESIS_WORKSPACE.md)를 참고하세요.

### 공시 원문 작업면 — AI 없이 직접 확인

관심종목 상세의 `공시 원문`에서 사업·반기·분기보고서를 선택해 원문을 수집합니다. 기존 DART 연결을 사용하며 OpenAI 키가 필요하지 않습니다. 목차의 사업 내용/주석/재무 분류와 검색, 원문 문단·표, 저장 버전 선택, DART 링크와 투자포인트 연결을 제공합니다. 데스크톱은 목차·본문 내부 스크롤, 모바일은 목차 선택 메뉴를 사용합니다.

원본 ZIP·추출본·해시·수집일·범위 경고를 로컬에 보존하고 백업합니다. 재수집 실패해도 이전 문서는 유지합니다. 정정본은 별도 접수번호이며 이미지·PDF·외부 첨부/OCR는 미지원입니다. 제목과 링크만으로 본문을 읽었다고 표시하지 않습니다. 열람은 AI 호출이나 검토 완료 처리를 하지 않습니다. 자세한 범위와 검증은 [공시 원문 작업면](docs/DART_SOURCE_READER.md)을 참고하세요.

### 내 가설 기반 AI 검증 질문 — 2A

관심종목 → 투자포인트 저장·선택 → `AI 질문` → `질문 제안 요청` → 전송할 저장본 확인·동의 → 질문 선택·수정·채택.

- `.env.local`의 `OPENAI_API_KEY`가 필요하며 설정 후 서버를 재시작합니다. 키 값은 채팅·화면·Git에 넣지 않습니다. 키 미설정이면 실행을 막고 기존 작성·수동 질문 기능은 유지합니다.
- 종목명·코드, 선택한 포인트의 제목·본문·확인 시기·반증 조건, 기존 질문만 전송합니다. 다른 포인트, 개인 기록, 관련 원문 링크 필드, 수집 자료는 제외합니다. 본문에 직접 쓴 내용은 전송 미리보기 그대로 포함됩니다.
- 최대 6개의 성립 조건·반증·가설 구체화 질문, 필요한 자료와 확인할 부분을 제안합니다. `내 글에서` 인용은 **사용자 주장**이지 기업 사실을 입증하는 출처가 아닙니다. 실제 공시 본문을 읽거나 사실을 확인한 결과가 아닙니다.
- 채택한 질문만 기존 검증 항목 뒤에 추가하고 본문은 바꾸지 않습니다. 채택 후 직접 편집할 수 있습니다. 현재는 한 결과에서 한 번 묶음 채택하며, 같은 요청의 재전송은 중복 저장하지 않습니다.
- 요청 시점의 저장 버전·정확한 입력·모델·프롬프트·결과·오류·공급자가 보고한 토큰 사용량·채택 기록을 `thesis_ai_runs`에 보존합니다. 글이 바뀌면 이전 제안의 신규 채택을 막습니다. 입력/설정이 같은 성공 결과는 다시 사용하며 열람·새로고침으로 유료 호출하지 않습니다.
- `research/thesis-ai.json`에 모델·크기·출력·시간 제한을, `research/ai-request-policy.json`에 공유 한도를 둡니다. 질문 제안 기본 모델은 `gpt-5.6-terra`, 연결 자료 근거 검토는 `gpt-5.6-sol`이며 각각 환경변수로 바꾸면 호환성·품질을 다시 검증해야 합니다. 같은 SQLite 저장소를 쓰는 두 AI API가 진행 중 요청 1개와 시간당 한도를 공유합니다. 실패도 포함하며 계정 전체의 금액 상한은 아닙니다.
- 자동 유료 재시도는 없습니다. 서버 중단·결과 미확인 상태는 별도 표시하고 공급자의 비용 발생 여부는 사용량에서 확인해야 합니다. 백업에는 입력·결과·사용량·채택 기록이 포함되며, 진행 중 요청을 복구하더라도 자동 재전송하지 않습니다. 개인 글과 백업은 기본적으로 암호화되지 않습니다.
- 실제 모델은 오류·불완전·거절 응답과 형식/인용/표현 검사를 통과해야 표시합니다. 이 검사는 질문의 해석이나 유용성을 보증하지 않습니다.

검증: `npm run test:thesis-ai`, 기존 단위 테스트, Python 백업 테스트, 빌드 후 `node --experimental-strip-types tests/followup-api-smoke.mjs`. 테스트는 모의 모델 응답·격리 저장소를 사용합니다. 구현 시점에는 API 키가 없어 **실제 유료 호출·응답 품질은 미검증**입니다. [수동 품질 평가 세트](docs/THESIS_AI_EVALUATION.md)로 실제 응답을 확인한 후 원문 기반 대조로 확장합니다.

### 기존 AI 선정 근거 해설 — 기본 UI에서 제외

기존 Radar 해설 구현과 API는 호환성을 위해 남겨두었지만 종목 상세의 기본 실행 탭에서는 제외했습니다. 사용자 투자포인트를 이 API에 넣지 않습니다. 아래는 남아 있는 기존 구현의 범위이며 새 투자포인트 AI가 아닙니다.

- `.env.local`에 `OPENAI_API_KEY`를 설정하고 서버를 다시 시작하세요. 키는 채팅·화면·Git에 넣지 않습니다. 키 없이도 원래 수치와 고정 지표 설명은 확인할 수 있습니다.
- 버튼 클릭 시에만 공개 종목 정보와 해당 선정 근거를 OpenAI Responses API에 전송합니다. 관심종목 전체 목록·검토 기록·API 키는 입력 자료에 넣지 않습니다. `store: false`를 사용하지만 공급자의 보존 정책까지 없어진다는 의미는 아닙니다.
- AI는 최대 세 개의 짧은 설명·확인 질문을 만듭니다. 연결된 근거 ID가 없거나 숫자를 재작성한 답변, 금지된 투자 지시, 불완전·거절 응답은 표시하지 않습니다. 실제 수치는 원자료에서 별도로 표시하며, 출처 연결 검사만으로 해석의 정확성까지 보장하지 않습니다.
- 기존 선정 근거와 이후 수집한 재무를 섞지 않습니다. 반대 근거·누락·오래된 자료 경고는 AI가 생성하지 않고 별도로 보존합니다.
- `research/evidence-ai.json`: 모델·요청 크기·시간 제한·출력 길이·캐시. 기본 모델은 `gpt-5.4-mini-2026-03-17`, 동일 근거/설정 답변은 24시간 재사용합니다. 라우트는 새 가설 AI와 SQLite 요청 한도를 공유합니다. 자동 재시도 없음. 이는 계정 전체의 비용 상한이 아닙니다.
- 캐시·호출 기록은 Git 제외 경로 `data/cache/evidence-ai`에 저장하며 필요하면 `EVIDENCE_AI_CACHE_DIR`로 분리합니다. 실패 요청도 횟수에 포함합니다. 모델은 `EVIDENCE_AI_MODEL`로 변경할 수 있으나 호환성·품질을 다시 확인해야 합니다.
- API: `GET /api/stocks/{code}/evidence?lens=...`는 근거/캐시만 조회합니다. `POST`는 `lens`, `revision`만 받고 서버가 근거를 재구성합니다. 다른 사이트 요청과 변경된 근거 버전은 거부합니다.

검증: `npm run test:evidence`, 빌드 후 `node --experimental-strip-types tests/followup-api-smoke.mjs`. 자동 테스트는 모의 응답과 격리 저장소를 사용하며 유료 API를 호출하지 않습니다. 현재 실제 모델 해설의 품질 검증은 API 키 설정 후 진행해야 합니다.

### Stock Detail v2

- `/stocks/{code}`: 핵심 현황, 재무 추이(8개 지표·차트/수치표), 실제 가격과 거래량(1개월/3개월/1년/전체), 유형별 공시 타임라인.
- 좌우 패널은 접기/펼치기, 좁은 화면에서는 서랍으로 표시합니다. 본문·목록·우측 패널은 독립 스크롤입니다.
- 자료 출처, 기준 분기, 연결 실행과 계산식은 우측 `지표·출처`에 표시합니다. 관심종목 보강 후에는 최근 1년 전체 공시 유형을 조회하며 분기별 재무 원문도 연결합니다.
- 원 자료의 금액을 억원으로 단위 환산하며 지수화하지 않습니다. 결측은 0 대신 null/차트의 끊김으로 유지합니다.
- 기존 `ev_ebitda` 저장값은 실제로 EV/영업이익 근사치이므로 상세 자료에서는 `ev_operating_profit`으로 내보냅니다. ROE는 평균자본이 아닌 기말자본 기준임을 표시합니다.
- 과거 Radar 보강기의 첫 비1분기 현금흐름은 누적자료일 수 있습니다. 신규 관심종목 수집기는 해당 연도의 앞선 보고서까지 가져와 단독 분기로 계산하고, 원화·연결/별도·연속성·접수번호를 확인합니다. 기존 Radar 판정 자체는 이 작업에서 재평가하지 않습니다.
- `generated_at`과 각 출처의 실제 수집 시점을 구분합니다. 투자포인트 저장과 자료 갱신은 AI를 호출하지 않습니다.

### 관심종목 워크플로

- Radar는 `scripts.export_radar_previews`로 가격·기본 지표만 게시합니다. 전체 후보의 심화 자료를 미리 생성하지 않습니다.
- 후보 미리보기나 Radar 우측 패널에서 관심종목 등록 → 등록 즉시 저장 → 분리된 Python 작업에서 가격, 재무, 공시를 보강합니다. 진행 상태와 자료는 화면 이동/새로고침 이후에도 유지됩니다.
- `/watchlist`와 상세 좌측 패널에서 등록한 종목을 탐색합니다. 새로운 Radar 결과에 없더라도 그대로 유지합니다.
- 로컬 영구 저장: `data/research/watchlist.sqlite`(등록·작업 상태·자료), `data/research/raw/`(재무 원자료). 둘 다 Git에서 제외합니다. 백업 시 디렉터리 전체를 보관하세요. 브라우저 저장소를 원본으로 쓰지 않습니다.
- API: `GET /api/watchlist`, `GET/PUT/DELETE /api/watchlist/{code}`, `POST /api/watchlist/{code}` with `mode: all | retry`. 등록은 idempotent하며 종목당 실행 하나만 허용합니다. 해제는 논리적 숨김으로 자료를 지우지 않습니다.
- 가격·재무·공시 단위로 성공/실패를 보존하고, 실패 재시도는 성공한 출처를 재수집하지 않습니다. 재무 일부 보고서가 실패하면 성공한 원자료를 저장해 재시도에 재사용합니다. 기존 화면 자료는 실패로 덮어쓰지 않습니다.
- `research/config.json`에 경로·상태 폴링·수집 범위를 정의합니다. `RESEARCH_STORAGE_DIR`은 테스트/로컬 데이터 분리용 선택 환경변수입니다. 수집기는 서버의 `DART_API_KEY`를 사용하며 키와 원본 예외 URL을 API 응답에 노출하지 않습니다.
- 현재 로컬 SQLite를 원본 저장소로 사용하며 시작 전/수동 백업과 새 폴더 복구를 제공합니다. 모바일 배포는 이 DB를 직접 열지 않고 게시된 축약 스냅샷만 읽습니다.

## 비공개 모바일 배포 준비

Vercel Functions의 파일시스템은 영구 저장소가 아니므로 로컬 SQLite를 그대로
배포하지 않습니다. 구조는 `로컬 원본 → Supabase 스냅샷 → Vercel 모바일 화면`이며,
역방향은 `모바일 메모 → Supabase → 로컬 리서치 로그`입니다. Radar·자료 최신화·AI
버튼은 모바일 화면에 두지 않습니다.

1. Supabase 프로젝트 SQL Editor에서 `supabase/mobile-dashboard.sql`을 한 번 실행합니다.
2. `.env.local`에 `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, 서로 다른 긴 값의
   `MOBILE_ACCESS_PASSWORD`, `MOBILE_SESSION_SECRET`을 추가합니다.
3. 로컬에서 `npm run mobile:publish`로 현재 스냅샷을 게시합니다.
4. Vercel Production 환경에는 위 네 값과 `DASHBOARD_MODE=mobile`을 설정합니다.
   `OPENAI_API_KEY`, `DART_API_KEY`, 로컬 경로는 모바일 배포에 넣지 않습니다.
5. 모바일 메모를 PC 리서치 로그로 가져온 뒤 새 스냅샷을 올릴 때
   `npm run mobile:sync`를 실행합니다.

`SUPABASE_SECRET_KEY`와 세션 비밀키는 서버·로컬 스크립트에서만 사용하며
`NEXT_PUBLIC_` 접두사를 붙이지 않습니다. SQL은 anon/authenticated 권한을 철회하고
RLS를 활성화합니다. 배포 모드는 기존 로컬 API를 404 처리하고 `/mobile`로 이동시킵니다.
로컬 원본과 모바일 스냅샷은 자동 실시간 동기화가 아니며, 마지막 게시 시각을 화면에
표시합니다.

원자료 해석 기준: [DART 전체 재무제표 가이드](https://engopendart.fss.or.kr/guide/detail.do?apiGrpCd=DE003&apiId=AE00036), [DART 공시검색 가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001).

검증: `npm run test:stock`, `.venv\\Scripts\\python.exe -m unittest discover -s tests -p "test_*.py"`, `npm run lint`, `npm run build`.
